# City Adapters

City adapters are small, reproducible transformations from local public data into the normalized Bims city atlas contract.

## Current Configs

- `config/cities/london.json`: default public atlas city. Generated artifacts combine the London discovery catalog with paginated row-level Planning Data brownfield/designation records, LFB incidents, TfL disruptions, and curated milestone events.
- `config/cities/nyc.json`: first US atlas city. Generated artifacts combine the NYC discovery catalog with partial DOB/DOB NOW, DOT, ZAP, HPD housing, capital-project, parks, tree-census, permitted-event, 311, collision, and curated milestone events.
- `config/cities/belfast.json`: existing local pilot with normalized events generated from the Belfast catalog.

## Adapter Contract

An adapter should produce normalized event records with:

- Stable ids.
- Effective dates or date ranges.
- GeoJSON geometry or an affected area label.
- Source ids from `config/source_registry.json`.
- Evidence URLs, local file paths, or source record ids.
- Confidence and caveats.
- Transformation provenance.
- Lens compatibility through the shared 15-lens contract.

Write static output under:

```text
web/data/city-atlas/cities/<city_id>/
```

Do not require a database for MVP ingestion. Large source files can stay outside git; commit small fixtures, metadata, checksums, and generated browser chunks.

## 15-Lens Contract

Launched cities must expose every lens from `docs/15_lens_city_design_contract.md`.
For the current public atlas this means Belfast City Council, Greater London,
and all five NYC boroughs each have a generated `lens_manifest.json` with 15
source-backed lenses.

Run:

```powershell
npm run build:lens-contract
npm run verify:lens-contract
```

The builder reads normalized events and sources, then writes city and top-level
manifests under `web/data/city-atlas/`. The verifier fails missing lenses,
missing official boundary scope, zero compatible event/source counts, missing
licence URLs, missing attribution, missing freshness notes, missing export
flags, weak provenance, and missing reference-screen coverage.

## Adding A City

1. Add `config/cities/<city_id>.json`.
2. Add or reuse source entries in `config/source_registry.json`.
3. Add an adapter path in `scripts/build_data.js` or a helper script called by it.
4. Generate `events_<year>.json` and `events_<year>.geojson` chunks.
5. Run `npm run build:data`.
6. Run `npm run build:lens-contract`.
7. Run `npm run verify:data`.
8. Run `npm run verify:lens-contract`.
9. Document source coverage, caveats, and contribution gaps.

## Recommended Adapter Boundaries

Keep raw parsing separate from normalization:

- Parser: reads CSV, JSON, GeoJSON, API exports, or source manifests.
- Normalizer: maps source rows into Bims event/source fields.
- Validator: checks source references, licences, attribution, years, and geometry.
- Writer: writes deterministic JSON/GeoJSON chunks.

## Belfast Notes

The Belfast adapter uses the infrastructure event catalog as an input. It downgrades OSM-derived records to `inferred` confidence because an OSM edit timestamp is not the same thing as an opening, construction, or demolition date.

Official project pages and planning statistics can be `documented`, but their caveats still travel with the event. A planning approval remains an administrative event unless a later source confirms completion.

## London And NYC Notes

London and NYC are no longer empty placeholders. They are source-backed adapters
built from `data-discovery/` and generated by
`scripts/build_discovery_city_atlas.py`. Each city exposes the full 15-lens
contract, but row-level historical event coverage is concentrated in the
datasets that currently have adapters. Treat dataset-layer markers as source
availability, not physical events. Row-level adapters should skip undated rows,
preserve source record URLs/retrieval timestamps, and record any API pagination
or event caps in raw summary metadata.
